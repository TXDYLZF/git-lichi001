# Linux 常用命令笔记（二）：权限与软链接

## 一、权限 644 是什么意思

`644` 是三位八进制权限，对应 `ls -l` 里的 `-rw-r--r--`。

```
6  4  4
│  │  └── 其他人 (o)
│  └───── 属组   (g)
└──────── 属主   (u)
```

基础值：`r=4`、`w=2`、`x=1`，每位相加。

| 数字 | 字母 | 能力 |
|---|---|---|
| 6 | `rw-` | 读 + 写 |
| 4 | `r--` | 只读 |

所以 `644` = 属主能读能写、同组只能读、其他人只能读，是**普通文件的默认权限**。

常见权限对照：

| 权限 | 字母 | 典型用途 |
|---|---|---|
| `600` | `rw-------` | 私密文件（密钥） |
| `644` | `rw-r--r--` | 普通文件（默认） |
| `755` | `rwxr-xr-x` | 可执行程序、目录 |
| `777` | `rwxrwxrwx` | 谁都能读写执行（⚠️ 危险，别随便给） |

目录的 `x` 表示「能否进入（cd）」，不是执行程序，所以目录至少 `r-x`(5)。

修改权限：

```bash
chmod 644 file.txt        # 整体设置
chmod u+x script.sh       # 只给属主加执行位
chmod go-w file.txt       # 去掉组和其他人的写权限
```

## 二、软链接（symbolic link）

**本质：软链接是一个独立的小文件，它的内容只存「目标的路径」**，类似 Windows 快捷方式。

```bash
ln -s docs/a.txt link_a   # 创建软链接
```

- `link_a` 有自己的 inode，类型是 `l`，体积只有几十字节，内容是字符串 `"docs/a.txt"`。
- 访问 `cat link_a` 时，内核发现是软链接，自动改去打开目标，把内容返回。
- 目录里相对路径的链接，**按链接所在目录解析**，不是按当前目录。

```bash
ls -l link_a                  # 看箭头 -> 指向哪
readlink link_a               # 只输出目标
readlink -f link_a            # 解析成绝对路径
ls -li link_a docs/a.txt      # 两个 inode 不同 → 证明是两个文件
```

### 软链接 vs 硬链接

| | 软链接 `ln -s` | 硬链接 `ln` |
|---|---|---|
| 本质 | 存「路径」的新文件 | 同一 inode 的另一个名字 |
| 跨文件系统 | 可以 | 不行 |
| 目标被删 | 变成悬空链接 | 不受影响 |
| inode | 独立 | 与目标相同 |

### 悬空链接（broken link）

目标被删除后，链接文件还在，但跳不过去，`ls` 里会显示红色。

```bash
find ~/findlab -xtype l       # 找悬空链接
```

`-type l` 查链接自身；`-xtype l` 查「链接有效但目标不存在」，别混。

## 三、系统里的真实例子

```bash
ls -l /etc/mtab                  # -> /proc/mounts
ls -l /etc/rc1.d/S02single       # -> ../init.d/single
ls -l /etc/rc2.d/ | head         # 一堆 S01xxx -> ../init.d/xxx
```

- `/etc/rcN.d/` 里的 `K01xxx`、`S02xxx` 全是软链接，指向 `/etc/init.d/` 下的脚本。
- `K` = kill（停服务），`S` = start（起服务），中间两位数决定执行顺序。
- **一个脚本 + 不同 runlevel 目录里的不同链接名**，实现「在不同状态下启动或停止服务」——这是 SysV init 的设计思想：用文件而不是配置。
- 嵌入式里 BusyBox init 用的还是 `/etc/init.d/rcS` 这套结构。

## 四、踩坑记录

- Linux 路径 `/d/github-work/...` 是 Windows Git Bash 的写法，在 Linux 虚机里不存在，会报 `No such file or directory`。
- 找**命令**在哪用 `which` / `type` / `whereis`；找**文件**才用 `find`。
- 想从虚机访问 Windows 文件，只能走挂载的共享目录 `/mnt/hgfs/share`，看不到整个 D 盘。
