# Linux 笔记（三）：用户管理——四个配置文件

> 来源：课堂笔记（2026-09-14）。Linux 里"用户"不只是一个名字，而是一整套数据库，就存在这四个文本文件里。

## 一、总览：谁管什么

| 文件 | 管什么 | 权限 |
|------|--------|------|
| `/etc/passwd` | 用户列表（基本信息） | 所有人可读 |
| `/etc/shadow` | 用户**密码**（加密存储） | **仅 root 可读** |
| `/etc/group` | 用户组列表 | 所有人可读 |
| `/etc/gshadow` | 组密码 / 组管理员 | **仅 root 可读** |

记忆：**明文的公开，加密的锁死**。密码相关的一律 shadow（影子），跟在明文文件"背后"。

```bash
more /etc/passwd    # 任何人都能看
sudo more /etc/shadow   # 必须 sudo
```

## 二、/etc/passwd：一行一个用户，七字段

```
softeem:x:1000:1000:softeem:/home/softeem:/bin/bash
   ↑    ↑   ↑    ↑      ↑         ↑          ↑
  ①    ②   ③   ④      ⑤         ⑥          ⑦
```

| # | 字段 | 本例值 | 说明 |
|---|------|--------|------|
| ① | 用户名 | softeem | 登录用的名字 |
| ② | 密码占位 | x | **真密码在 shadow 里**，这里只放个 x |
| ③ | UID | 1000 | 用户编号，**系统认 UID 不认名字**。0=root，1-999 系统用户，1000+ 普通用户 |
| ④ | GID | 1000 | 主组编号（对应 /etc/group） |
| ⑤ | 描述 | softeem | 全名/备注，可空 |
| ⑥ | 家目录 | /home/softeem | 登录后落地的位置 |
| ⑦ | Shell | /bin/bash | 登录后用的解释器；`/sbin/nologin` = 禁止登录（系统账号标配） |

## 三、/etc/shadow：为什么密码要单独一个文件

```
softeem:$6$xxxx...:19000:0:99999:7:::
```

- `$6$` 开头表示 **SHA-512 加密**（$1$=MD5，$5$=SHA-256）
- 后面还带**有效期策略**字段（最短/最长使用天数、过期前警告天数）

**为什么拆出来**：passwd 人人可读（很多程序要查用户名↔UID），如果密码哈希也放里面，等于把锁芯挂门外给别人慢慢爆破。shadow 只给 root 读，权限 `000`/`400`——**把"通讯录"和"保险柜"分开存放**。

## 四、/etc/group 与 gshadow

```
sudo:x:27:softeem
  ↑  ↑  ↑    ↑
组名 密码占位 GID  附加成员（逗号分隔）
```

- 一个用户有**一个主组**（passwd 第 ④ 字段）+ **多个附加组**（列在这里）
- 附加组是授权的关键：把 softeem 加进 `sudo` 组，它就有 sudo 权限——`usermod -aG sudo softeem`
- gshadow 存组密码（临时提权用，现在几乎不用了）+ 组管理员

## 五、速查：改这四个文件的正确姿势

```bash
useradd  -m -s /bin/bash dev1   # 建用户（-m 建家目录，-s 指定 shell）
passwd   dev1                   # 设/改密码（写进 shadow）
usermod  -aG sudo dev1          # 加进附加组（group 里追加一行）
userdel  -r dev1                # 删用户并清家目录
id       dev1                   # 查 UID/GID/所属组（不改文件，只读）
```

**原则：永远用命令改，不直接编辑文件**——命令保证字段格式、备份和一致性；手改一个冒号错位，整个用户就登不上了。

## 六、嵌入式视角

- 嵌入式 rootfs 里**同样有这四个文件**（busybox 生成），`ls /etc/passwd` 就能确认
- 很多板子出厂 shadow 里 root 密码字段为空——**空 ≠ 没密码，是免密登录**，量产设备必改
- `/sbin/nologin`（passwd 第 ⑦ 字段）在嵌入式里是给 ftp/ssh 服务账号禁 shell 的标准手法
- 用户权限模型直接对应驱动开发：设备文件 `/dev/ttyS0` 的属主/属组决定哪个进程能打开串口
