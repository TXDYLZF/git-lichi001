# 07 指针专题：完整知识点与经典易错点

> 配套 [03 位运算与指针](03-位运算与指针.md) 已覆盖：解引用、`&` 与 `*` 互逆、`*p++` 与 `(*p)++`、寄存器/硬件地址操作。
> 本文补全**指针完整体系** + 考试最爱的**经典易错点**（全部经本机 gcc 实测）。
>
> ⚠️ 环境差异提醒：本机是 **32 位 MinGW**，指针占 **4 字节**；机房 RHEL8 一般是 **64 位**，指针占 **8 字节**。笔记里凡涉及"指针多大""数组退化后 sizeof 多少"，课堂数字可能是本机的 2 倍，别慌，规则一样。

---

## 一、指针的本质（先建立心智模型）

**结论**：指针就是**存内存地址**的变量；它自己占一块内存，里面放的是"另一块内存的门牌号"。

**原因**：C 里每个变量都在内存有地址。指针存这个地址，就能间接找到并读写那块内存——这是"间接访问"。

**写法**：
```c
int a = 10;
int *p = &a;     /* p 里存的是 a 的地址；p 指向 a */
printf("%d %d\n", a, *p);   /* 10 10 */
```

内存模型（画给你记）：
```
变量 a:  [ 10 ]  地址 0x1000
指针 p:  [0x1000] 地址 0x2000   ← p 自己也有地址和空间
            ↑ p 里装的 0x1000 指向 a
```

**指针变量自己占多大？** 取决于编译环境：
- 32 位程序：**4 字节**（本机 MinGW 实测 `sizeof(int*) = 4`）
- 64 位程序：**8 字节**（机房 RHEL8 通常如此）

---

## 二、取地址 `&` 与 解引用 `*`（速记，详述见 03）

- `&a`：取 a 的地址（从变量 → 地址）
- `*p`：取 p 指向的变量（从地址 → 变量），可读可写
- 互逆：`*&a == a`、`&*p == p`（见 03 实测）
- 同一个 `*` 两种身份：**声明里**只标记"这是指针"，**表达式里**才真解引用。`int *p, q;` 里 **q 只是普通 int**。

---

## 三、指针的"类型"决定两件事（核心，必考）

**结论**：指针类型不是装饰，它决定编译器怎么用这个指针——解引用读几字节、+1 走几字节。

**原因**：`int*` 和 `double*` 指向的东西大小不同，编译器必须知道按几字节解释、指针移动多少。

**实测**（本机）：
```c
int x[3] = {0};
int *pi = x;
double *pd = (double*)x;
/* pi      = 0x...EEC */
/* pi + 1  = 0x...EF0  (差 4 = sizeof(int)) */
/* pd      = 0x...EEC */
/* pd + 1  = 0x...EF4  (差 8 = sizeof(double)) */
```
**写法/记忆**："类型即刻度"。`p+1` 不是地址 +1，是地址 + `sizeof(*p)`。

## 四、指针运算（合法的只有四类）

| 运算 | 含义 | 注意 |
|------|------|------|
| `p + n` / `p - n` | 移动 n 个元素 | 步长 = `sizeof(类型)` |
| `p1 - p2` | 两指针相隔几个元素 | **必须指向同一数组**，结果是 `((char*)p1-(char*)p2)/sizeof(类型)` |
| `p++` / `p--` | 前进/后退一个元素 | 常用于遍历 |
| `p1 < p2` / `==` | 比较地址先后/相等 | 同样只在同数组内有意义 |

**非法**：指针 + 指针、指针 × 指针都不允许（编译报错）。

> `*p++` 与 `(*p)++` 的优先级实战见 03，那是你的头号易错点（错题本第 12 条），此处不重复。

## 五、指针与数组（重中之重）

### 5.1 数组名 = 首元素地址（但不是指针变量）

**结论**：`int a[5];` 里 `a` 的值就是 `&a[0]`，但 `a` 是**常量**，不是可改的指针变量。

**原因**：数组名在绝大多数语境下退化成首地址，但它没有自己的存储位置，不能被赋值或 `++`。

**实测**：`a++;` → 编译报错 `lvalue required as increment operand`（见经典易错点第 3 条）。

### 5.2 `a[i]` 等价于 `*(a + i)`

**结论**：下标访问本质就是指针算术：`a[i] == *(a+i) == *(i+a) == i[a]`。

**写法/记忆**：`a[3]` 就是"从首地址走 3 步，取那个格子"。所以指针也能当数组用：`int *p=a; p[3]` 就是 `a[3]`。

### 5.3 指针遍历数组

```c
int a[5] = {1,2,3,4,5};
for (int *p = a; p < a + 5; p++)
    printf("%d ", *p);     /* 1 2 3 4 5 */
```

### 5.4 数组传参会"退化"成指针（经典大坑）

**结论**：`void f(int a[])` 和 `void f(int *a)` **完全等价**；函数内 `sizeof(a)` 拿到的是**指针大小**，不是数组大小。

**原因**：C 不允许整个数组按值传参，传进去的其实是首地址，形参本质是 `int*`。

**实测**（本机 32 位，指针 4 字节）：
```c
int arr[5];
sizeof(arr);          /* 20 = 5*4，数组原貌 */
void f(int a[]) { sizeof(a); }   /* 4，已退化为 int* */
```
**正确写法**：数组长度必须**单独作为参数**传进去：`void f(int a[], int n)`。

## 六、指针与字符串

### 6.1 两种写法，天差地别

```c
char *s = "hello";    /* s 指向只读常量区的字符串字面量 */
char  t[] = "hello";  /* t 是在栈上的字符数组，内容可改 */
```

**结论**：`char*` 指向的字面量**不能修改**；`char[]` 数组里的字符串**可以修改**。

**原因**：字符串字面量通常放在只读数据段，强行写会触发保护。

**实测**：`char *s="hello"; s[0]='H';` → **段错误**（本机 exit 139）。

### 6.2 指针遍历字符串（靠 `'\0'` 结束）

```c
char *s = "hello";
while (*s) putchar(*s++);   /* 打印 hello，遇到 '\0' 停止 */
```

## 七、指针作函数参数（传址调用）

**结论**：想在函数里**改外部变量**，或函数要**返回多个结果**，就传指针。

**原因**：C 是值传递，传指针才能让函数操作同一块内存，而不是副本。

**写法**：
```c
void swap(int *x, int *y) { int t = *x; *x = *y; *y = t; }
/* 调用： swap(&a, &b); */

/* 返回多个值：用指针参数"带出来" */
void divmod(int a, int b, int *q, int *r) { *q = a/b; *r = a%b; }
```

## 八、动态内存 `malloc` / `calloc` / `realloc` / `free`

**结论**：运行时才知大小的内存用 `malloc` 从**堆**申请，用完必须 `free`，且 `free` 后立刻置 `NULL`。

**原因**：堆内存不会随函数返回自动回收；不 `free` 会泄漏，乱用会崩。

| 函数 | 特点 |
|------|------|
| `malloc(n)` | 申请 n 字节，**不初始化**（内容是垃圾） |
| `calloc(c, s)` | 申请 `c*s` 字节并**全部清零** |
| `realloc(p, n)` | 把 p 指向的内存**扩容/缩容**到 n 字节 |
| `free(p)` | 归还内存；**只能 free malloc 系列返回的起始地址** |

**实测**（判空 + free 后置 NULL）：
```c
int *p = (int*)malloc(5 * sizeof(int));
if (p == NULL) { /* 申请失败，绝不往下用 */ }
p[3] = 30;
free(p);
p = NULL;        /* 关键：避免悬空指针 */
```

## 九、NULL / 野指针 / 悬空指针（三大危险指针）

| 类型 | 怎么来的 | 危害 |
|------|---------|------|
| **野指针** | 定义指针没初始化，`int *p;` 就 `*p=5` | 指向随机地址，解引用 = 段错误/改坏别的数据 |
| **悬空指针** | `free(p)` 后没置 NULL，继续用 p | 内存已归还系统，再访问是未定义行为 |
| **NULL 指针** | 初始化为 `NULL` 或 free 后置 NULL | 解引用也崩，但**可判空防御** |

**铁律（上次截图那题）**：
1. 定义指针**当场初始化**，暂不指就 `int *p = NULL;`
2. `free` 之后**立刻 `p = NULL;`**
3. 用指针前 `if (p == NULL) return -1;`
4. 判空用 `NULL`，别用 `0`（语义更清晰）
5. **绝不返回局部变量的地址**（函数返回后栈帧销毁，那个地址变成悬空）

**实测**：`int *p; *p = 5;` → 段错误（exit 139）；返回局部变量地址 → 编译警告 `returns address of local variable`，运行时 UB。

## 十、`const` 与指针（4 种组合，看 `*` 在哪边）

**结论**：`const` 在 `*` **左边**保护"指向的数据"，在 `*` **右边**保护"指针本身"。

| 写法 | 含义 | 能否改 `*p` | 能否改 `p` |
|------|------|-----------|-----------|
| `const int *p` | 指向常量（数据不可改） | ❌ | ✅ |
| `int const *p` | 同上（两种写法等价） | ❌ | ✅ |
| `int * const p` | 常量指针（指针不可改） | ✅ | ❌ |
| `const int * const p` | 都不可改 | ❌ | ❌ |

**实测**：`int * const p = &x; p++;` → 编译报错 `increment of read-only variable 'p'`。

**记忆口诀**：**`const` 贴着 `*` 左边 = 锁数据，贴着右边 = 锁指针。**

---

## 十一、指针数组 vs 数组指针（语法最易混）

**结论**：看 `*` 先跟谁结合——`[]` 优先级高于 `*`，所以 `*` 先跟变量名的是指针。

| 写法 | 是什么 | 读法 |
|------|--------|------|
| `int *p[10]` | **指针数组**：10 个 `int*` 元素的数组 | p 是数组，成员是指针 |
| `int (*p)[10]` | **数组指针**：指向"含 10 个 int 的数组"的指针 | p 是指针，指向整个数组 |

**实测**（本机 32 位，指针 4 字节）：
```c
int *p[3];    sizeof(p) = 12;   /* 3 个指针 */
int (*q)[3];  sizeof(q) = 4;    /* 1 个指针 */
```

---

## 十二、指针函数 vs 函数指针

| 写法 | 是什么 |
|------|--------|
| `int *f(int)` | **指针函数**：返回 `int*` 的函数 |
| `int (*f)(int)` | **函数指针**：指向"返回 int、收 int"的函数的指针 |

**要点**：
- **函数名本身就是函数指针**（函数的入口地址），所以 `f` 和 `&f` 一样能赋给函数指针。
- 函数指针用来做**回调**：把函数当参数传，比如 `qsort` 的比较函数。
- 一句话区分：`()` 里有名字的是函数（指针函数），`()` 里没名字、被 `(*名)` 包着的是函数指针。

---

## 十三、二级指针 `int **pp`

**结论**：指向"指针"的指针，`pp` 里存的是某个 `int*` 的地址。

**用途**：
1. 要在函数里**改一个一级指针本身**（比如让它指向新申请的内存）——传 `int**`。
2. 指向"字符串数组"：`char *argv[]` 传给 `main` 时退化成 `char **argv`。

```c
int a = 5;
int *p = &a;
int **pp = &p;
printf("%d\n", **pp);   /* 5：解两次引用 */
```

## 十四、`void*` 通用指针

**结论**：`void*` 能指向任意类型，但**不知道指向什么类型**，所以不能直接解引用，也不能做指针算术。

**原因**：解引用需要知道读几字节，`void` 没有大小信息。

**用法**：
- `malloc` 返回 `void*`，在 **C 里可隐式转**成任意指针（C++ 必须强转）。
- 通用接口（如 `memcpy`、`qsort` 的比较参数）用 `void*` 接收任意类型。

**实测**：`void *vp = &x; *vp;` → 编译报错 `invalid use of void expression`。正确：`*(int*)vp`。

## 十五、经典易错点（考试重点！错写法 → 为什么错 → 正确写法）

> 这一节是考卷和高频口头提问的重灾区，逐条背。

### 1. 未初始化就解引用（野指针）
```c
int *p;      /* 错：p 里是随机垃圾地址 */
*p = 5;      /* 错：往随机地址写，段错误/改坏数据（实测段错误） */
```
✅ `int *p = NULL;` 或 `int *p = &a;`

### 2. 返回局部变量的地址
```c
int* bad() { int t = 10; return &t; }   /* 错：t 的栈帧函数返回即销毁 */
```
✅ 要么传指针让调用者提供空间，要么 `static`，要么 `malloc`（记得 free）。

### 3. 把数组名当指针变量 `a++`
```c
int a[5]; a++;    /* 错：数组名是常量，不是左值（编译报错 lvalue required） */
```
✅ 想移动就用另一个指针：`int *p = a; p++;`

### 4. `scanf` 漏写 `&`
```c
int a; scanf("%d", a);    /* 错：把 a 的值当地址往里写，崩 */
```
✅ `scanf("%d", &a);`（数组名、字符串指针本身已是地址，不用加 `&`）

### 5. 数组越界（指针走过尾部）
```c
int a[5]; int *p = a;
for (int i = 0; i <= 5; i++) p[i] = i;   /* 错：i=5 越界写 a[5] */
```
✅ 循环条件用 `i < 5`；指针遍历用 `p < a + 5` 收口。

### 6. `malloc` 不判 `NULL` 直接用
```c
int *p = malloc(n); *p = 1;   /* 错：申请失败返回 NULL，解引用崩 */
```
✅ `if (p == NULL) { 处理失败; return; }`

### 7. `free` 后继续用（悬空指针）
```c
free(p); *p = 1;   /* 错：内存已归还，再写是未定义行为 */
```
✅ `free(p); p = NULL;` 之后用前判空。

### 8. 对同一指针 `free` 两次（double free）
```c
free(p); free(p);   /* 错：未定义行为 */
```
⚠️ **平台差异**：本机 MinGW 实测**没崩**（exit 0），但 **Linux/glibc 通常直接 abort**，报 `double free or corruption`。**绝不能依赖"没崩"**。正确：`free(p); p = NULL;`，第二个 free 前判空即可避免。

### 9. 内存泄漏（丢了指向堆的指针）
```c
while (1) { int *p = malloc(100); }   /* 错：每次都申请从不 free，堆被吃光 */
```
✅ 每个 `malloc` 都要有对应的 `free`，且 free 前别弄丢指针。

### 10. 把字符串字面量当可写数组
```c
char *s = "hello"; s[0] = 'H';   /* 错：字面量在只读区，段错误（实测段错误） */
```
✅ 需要修改就用数组：`char s[] = "hello";`

### 11. `sizeof(数组)` 与 `sizeof(指针)` 混淆（传参后退化）
```c
void f(int a[]) { int n = sizeof(a)/sizeof(a[0]); }  /* 错：a 已退化为指针，n 算错 */
```
✅ 长度 n 单独传参；或用 `int a[][N]` 二维时，第一维也能退化，传参时务必带其余维度大小。

### 12. 指针相减/比较跨数组
```c
int a[3], b[3]; if (&a[2] - &b[0] > 0) ...   /* 错：不同数组相减无意义，UB */
```
✅ 只在指向同一数组的指针间做减法/比较。

### 13. 同一表达式里对同一对象改两次（序列点 UB）
```c
*p++ = (*p)++;          /* 错：一个表达式内多次修改 p 指向的对象，未定义行为 */
```
✅ 副作用拆到不同语句写（见 03 / 错题本第 12 条）。

### 14. 混淆指针数组/数组指针、函数指针语法
```c
int (*p)[10];  /* 是数组指针，不是"10 个指针的数组" */
int *p[10];    /* 才是指针数组 */
```
✅ 口诀：`[]` 优先级高于 `*`，`*` 先贴变量名就是指针。

### 15. 指针类型强转后按错字节读
```c
int a = 0x12345678;
short *ps = (short*)&a;
printf("%d\n", *ps);    /* 错/坑：只读了低 2 字节，且涉及大小端 */
```
✅ 强转只改"解释方式"，不改内存；跨类型读会踩大小端和越界，尽量用同类型。

## 十六、追问预判（口头答题稿）

| 老师可能问 | 怎么答（结论 → 原因 → 写法） |
|-----------|------------------------------|
| 指针是什么？ | 存地址的变量；为了间接访问内存；`int *p=&a;` |
| 指针占几个字节？ | 看环境，32 位 4 字节、64 位 8 字节；本机实测 4 |
| 为什么 `p+1` 不是地址+1？ | 指针类型决定步长，+1 走 `sizeof(类型)` 字节；`int*` 走 4、`double*` 走 8 |
| 数组名为啥不能 `a++`？ | 数组名是常量（首地址），不是可改的左值；想动就用另一个指针 |
| 数组传参为啥拿不到长度？ | 退化成 `int*`，`sizeof` 拿到指针大小；长度要单独传 |
| `a[i]` 和 `*(a+i)` 啥关系？ | 完全等价，下标本质是指针算术 |
| `const int *p` 和 `int * const p` 区别？ | 前者锁数据（*p 不可改），后者锁指针（p 不可改）；看 const 在 `*` 哪边 |
| `malloc` 后要做什么？ | 判 NULL、用完 free、free 后置 NULL，防泄漏和悬空 |
| 什么是野指针/悬空指针？ | 野=未初始化；悬=free 后没置 NULL 还在用；都要 NULL 防御 |
| 二级指针干嘛用？ | 在函数里改一级指针本身，或指向字符串数组 `char**` |
| 函数指针有什么用？ | 把函数当参数传（回调），如 `qsort` 的比较函数 |

## 十七、嵌入式关联（往底层靠一程）

- **直接操作硬件地址**：`*(volatile unsigned int*)0x40023830 = 0x1;` —— 裸地址强转成指针再解引用，和 `*p=30` 是同一个动作，只是目标从内存换成外设寄存器。嵌入式读写寄存器全靠它。
- **野指针/悬空在嵌入式 = 跑飞**：裸机没有操作系统给的"段错误"保护，解引用一个坏地址往往直接硬件异常或改坏关键数据，**比在 Linux 上更致命**。所以"定义即初始化、free 后置 NULL"在驱动/裸机代码里是铁律。
- **`const` 用于只读资源**：`const` 变量常放进 Flash/只读段，防误改硬件配置表。
- **`void*` 在通用接口**：DMA 缓冲区、内存拷贝 `memcpy`、消息队列等不关心具体类型的场景，用 `void*` 做通用载体。
- **指针遍历缓冲区**：串口/DMA 接收环形缓冲区时，`*p++` 取当前字节再前进，是嵌入式里最高频的指针用法之一（详见 03 的 `*p++`）。
