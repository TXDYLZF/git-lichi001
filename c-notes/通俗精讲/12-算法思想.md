# 12 算法思想（大白话版）

> 来源：QQ `07.md`（递归 / 二分查找 / 动态规划 / inline 优化 / 死代码 / 合并常量）

不止「语法」，C 语言课还讲**怎么把问题拆成能跑的算法**。这篇讲三种最常考的：递归、二分、动态规划，顺带 inline 优化。

---

## 1. 递归：函数自己调自己

适合「问题能化成同结构的小问题」——阶乘、斐波那契、树/链表遍历。

```c
unsigned long long factorial(unsigned int n) {
  if (n == 1) return 1;            // ① 结束条件（基线）
  return n * factorial(n - 1);     // ② 自己调自己，规模变小
}
```

**递归两大铁律**（缺一不可，否则死循环爆栈）：
1. **有结束点**（基线 case）。
2. **每次调用都离结束点更近**（n-1 越来越小，终会到 1）。

斐波那契：`fib(n) = fib(n-1) + fib(n-2)`，基线 `n<=1` 返回 n。

⚠️ 朴素递归算 fib 会**重复算大量子问题**（指数级）。解法见下文动态规划。

## 2. 二分查找：递归的典型好例子

前提：**数组已排序**。每次砍掉一半：

```c
int binarySearch(int arr[], int left, int right, int x) {
  if (right < left) return -1;                 // 找完没找到
  int mid = left + (right - left) / 2;          // 防溢出写法
  if (arr[mid] == x) return mid;
  if (arr[mid] > x) return binarySearch(arr, left, mid - 1, x);   // 去左半
  return binarySearch(arr, mid + 1, right, x);                    // 去右半
}
// arr={1..8}, 找 6 → 返回下标 5
```

**为什么 `mid = left + (right-left)/2` 而不是 `(left+right)/2`**：当 left、right 都很大时，`left+right` 可能**溢出** int。这是面试常考点。

## 3. 动态规划：记住算过的，别重复算

朴素递归 fib 慢，是因为 `fib(5)` 算了两次 `fib(3)`、`fib(4)` 又算一遍……用**备忘录（memo）**把结果存起来，算过直接取：

```c
#define MAX 100
int memo[MAX];
void initMemo() { for (int i=0;i<MAX;i++) memo[i]=-1; }

int fib(int n) {
  if (n <= 1) return n;
  if (memo[n] != -1) return memo[n];     // 算过就直接返回
  return memo[n] = fib(n-1) + fib(n-2);  // 没算过就存起来
}
```

这一下把指数级降到**线性**。本质思想：**把复杂问题拆成重叠子问题，子问题结果复用**。

> 更进一步的「自底向上」迭代写法（不用递归）也是 DP，考试常让两种都写。

## 4. inline 优化：编译期替你「展开」

`inline` 建议编译器在调用处**直接把函数体贴进去**，省一次函数调用的开销（高频小函数用）。配合优化级别：

```
gcc main.c -o main       # 默认 O0，不优化（开发调试用，行为明确）
gcc main.c -o main -O1   # 基础优化
gcc main.c -o main -O2   # 中等优化（生产环境常用）
gcc main.c -o main -O3   # 最高优化（向量化）
```

编译器在优化阶段还会做：
- **死代码消除**：永远不会执行 / 对结果无影响的代码直接删掉（减小体积、提速）。
- **合并常量表达式**：`int x = 3+5-2;` 直接当成 `x=6`；`square(2)` 直接当成 `4`。

**inline vs 宏**：inline 做类型检查、可调试、无副作用；宏只做文本替换、易踩坑（详见 [11-预处理](11-预处理与头文件.md)）。高频小工具优先写 `static inline` 函数而非宏。

## 5. 一张图：递归怎么「压栈」

```
factorial(4)
 └─ 4 * factorial(3)
         └─ 3 * factorial(2)
                 └─ 2 * factorial(1)
                         └─ return 1   ← 基线，开始往回乘
         → 2*1=2 → 3*2=6 → 4*6=24
```

每次调用都把「现场」压进栈，到基线后一层层弹栈返回。层数太深会**栈溢出**（stack overflow）。

## 自测
- 递归必须有的两个条件？→ 结束点（基线）+ 每次调用离结束点更近
- 二分查找前提？→ 数组必须**已排序**
- `mid = (left+right)/2` 为什么可能错？→ left+right 大时溢出；应写 `left+(right-left)/2`
- 朴素递归 fib 慢在哪？怎么救？→ 重复算子问题；用 memo（动态规划）缓存结果
