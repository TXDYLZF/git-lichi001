## 1. 定义 / 声明 / 调用

```c
int add(int a, int b);   // 声明（函数原型）：告诉编译器「有这个函数，接口长这样」

int main() {
  int r = add(3, 4);     // 调用
  printf("%d\n", r);
}

int add(int a, int b) {  // 定义（函数体）
  return a + b;
}
```

- 不返回用 `void`；没参数写 `()` 或 `(void)`。
- 声明可省略函数体，通常放**头文件**或文件顶部；定义只能有一份。

## 2. 参数传递：值传递 vs 地址传递（头号考点）

> 这是理解指针的钥匙。详见 `09-指针通俗精讲.md` 第 0、7 节。

**值传递**：函数拿到的是实参的**复印件**，在函数里改形参，外面的原件**纹丝不动**。

```c
void modifyValue(int x) { x = 10; }
int main() {
  int x = 5;
  modifyValue(x);
  printf("%d\n", x);   // 还是 5
}
```

**地址传递**：把变量的**柜子编号（&x）**传进去，函数拿着编号去原件上改：

```c
void modifyValue(int *ptr) { *ptr = 10; }
int main() {
  int x = 5;
  modifyValue(&x);
  printf("%d\n", x);   // 10（改到了原件）
}
```

**口诀**：想让函数「带出」结果，就传指针（地址）。想交换两个数、返回多个值、在函数里改外面的变量，统统靠地址传递。

## 3. 返回值

- 有返回类型的函数必须 `return` 对应类型的值；`void` 函数可以 `return;`（或不写）。
- 想「返回多个值」：用指针参数带出来（`void divmod(int a,int b,int *q,int *r)`）。

```c
double divide(double a, double b) {
  if (b != 0) return a / b;
  return 0.0;
}
```

## 4. 作用域与生命周期

| 变量 | 在哪可见 | 生命周期 |
|------|---------|---------|
| 局部变量 | 定义它的函数内部 | 函数调用时创建、返回即销毁 |
| 全局变量 | 整个程序 | 程序启动到结束 |
| `static` 局部变量 | 函数内部 | **程序全程都在**，但只有该函数能访问（下一次调用还记得上次的值） |

```c
void counter() {
  static int count = 0;   // 只初始化一次
  count++;
  printf("count: %d\n", count);   // 调用3次 → 1 2 3
}
```

**全局变量要少用**：到处能改，debug 时不知道谁动的；能用参数传就别用全局。

## 5. static 函数 / 内联函数（inline）

- `static` 修饰函数：**只在当前源文件可见**，别的文件调不到——避免大项目里函数名撞车，利于模块化。
- `inline`：建议编译器在调用处**直接展开**代码，省一次函数调用开销（高频小函数用）。**是否真内联由编译器决定**，可加 `-O1` 等优化级别；`static inline` 在头文件里放小工具函数最常见。

```c
static inline int max(int a, int b) { return a > b ? a : b; }
```

> inline 与宏的差别：inline 做**类型检查**、可调试、无副作用；宏只做文本替换、易踩优先级坑。详见 [11-预处理](11-预处理与头文件.md)。

## 7. 头文件与跨文件（extern）

把函数声明放 `.h`、定义放 `.c`，别的文件 `#include "xxx.h"` 就能用。跨文件共享全局变量用 `extern` 声明（定义只在一处）。
**防护宏**防止头文件被重复包含：

```c
#ifndef UTILS_H
#define UTILS_H
extern int counter;
void increment_counter();
#endif
```

## 自测
- 值传递为什么改不了外面？→ 传的是复印件
- 想让函数改外面的变量怎么办？→ 传地址（`&x`），函数用指针接收
- `static` 局部变量和普通局部变量区别？→ static 全程存活、只初始化一次、下次调用保留值
- `inline` 一定会被内联吗？→ 不一定，编译器决定；加优化级别更易触发
