# 01 数据类型与存储（大白话版）

> 来源：QQ `02.md`（数据类型 / 补码 / 存储格式）+ 工作台 `01-数据类型.md`
> 配套详版：[01-数据类型.md](../01-数据类型.md)

把内存想成一排**带编号的储物柜**。一个「变量」就是向系统借了一个柜子，柜子里放数据；「数据类型」决定这个柜子**多大、怎么解释里面的 0/1**。

---

## 1. 基本类型一览（柜子有多大）

| 类型 | 通常大小 | 白话 |
|------|---------|------|
| `char` | 1 字节 | 一个字符（也常被当「超小整数」用，-128~127 或 0~255） |
| `short` | 2 字节 | 短整型 |
| `int` | 4 字节（32/64 位常见） | 默认整型，**平台自然大小** |
| `long` | 4 或 8 字节 | 至少 4 字节，`long >= int` |
| `long long` | 至少 8 字节 | 大整数 |
| `float` | 4 字节 | 单精度浮点 |
| `double` | 8 字节 | 双精度浮点 |
| `long double` | 12/16 字节（看平台） | 扩展精度 |

**平台差异提醒**：`int` 在 16 位机是 2 字节、32/64 位是 4 字节；**指针**在 32 位机 4 字节、64 位机 8 字节。做题时按老师给的位数算，叫 `sizeof` 说话最稳。

```c
printf("sizeof(int)=%zu\n", sizeof(int));      // 本机常见 4
printf("sizeof(char*)=%zu\n", sizeof(char*));   // 32位机4 / 64位机8
```

## 2. 有符号 vs 无符号（signed / unsigned）

- `signed int`（默认）：最高位当**符号位**，0 正 1 负。范围约 -21 亿 ~ 21 亿。
- `unsigned int`：没有符号位，全当数值。范围 0 ~ 42 亿。
- 适用：年龄、个数、下标这类**不可能是负数**的量，用 `unsigned` 能多一倍上限。

```c
char c = 65;            // 默认有符号 → 'A'
unsigned char uc = 255; // 无符号 → 0~255 全用上
```

**坑**：有符号数溢出是「未定义行为」；无符号数溢出是**回绕**（255+1 变 0），有时反而好预测，但别混用比较（`int` 和 `unsigned int` 比大小会先把 int 转成 unsigned，负数会变超大正数）。

## 3. 整数怎么存：二进制补码（必考）

> 课堂原话：正数直接用二进制；负数 = 绝对值的二进制**取反再加 1**。

```
+5  →  0000 0101        （原样）
-5  →  先取 +5 的反码 1111 1010，再加 1 → 1111 1011
```

验证：`-5` 的补码再加 1 的取反应该回到 5：

```c
int c1 = -5;
int c2 = ~c1 + 1;   // ~ 是按位取反；结果应该等于 5
printf("c1=%d, c2=%d\n", c1, c2);   // -5, 5
```

**为什么用补码**：让「减法」可以用「加法器」做（`a - b = a + (~b+1)`），硬件省一套电路。这点在嵌入式/汇编里天天见。

## 4. 浮点数为什么「不精确」：IEEE 754

`float` 4 字节 = 1 符号位 + 8 指数位 + 23 尾数；`double` 8 字节 = 1 + 11 + 52。
很多十进制小数（如 0.1）在二进制里是**无限循环小数**，只能近似存，所以：

```c
printf("%d\n", 0.1 + 0.2 == 0.3);   // 0（false！）
// 正确比法：看差是否足够小
int ok = fabs(0.1 + 0.2 - 0.3) <= 1e-9;  // 1（true）
```

**铁律**：浮点数**永远别用 `==` 直接比**，用「差的绝对值 < 一个很小的值」来比。

## 5. 构造类型（把柜子拼起来）

| 类型 | 白话 | 课堂笔记 |
|------|------|---------|
| 数组 | 一排**相同类型**的柜子，连在一起 | `02.md` 数据类型段 |
| 结构体 `struct` | 把**不同类型**的成员打包成一个柜子组 | `09.md` 详见 [08-结构体与联合体](08-结构体与联合体.md) |
| 共用体 `union` | 所有成员**共用同一块内存**，同一时刻只有一个有效 | 见下文第 6 节 |
| 枚举 `enum` | 一组**命名的整数常量**，让魔法数字变可读 | 见 [08](08-结构体与联合体.md) |
| 指针 | 柜子里放的是「别的柜子编号」 | 见 `09-指针通俗精讲.md`、[07-指针进阶](07-指针进阶.md) |
| `void` | 「没有类型」；`void*` 是万能指针 | 见 [07](07-指针进阶.md) |

```c
// 基本类型 + 构造类型 一起看
int age = 18;
struct student { int sid; char name[50]; };
struct student s1 = {1001, "jim"};
int *pAge = &age;
printf("point:%p, value:%d\n", pAge, *pAge);
```

## 6. 共用体 union（所有成员抢同一块内存）

`union` 的大小 = **最大成员**的大小，因为大家叠在一起放：

```c
union Data {
  int i;
  float f;
  char s[20];
};
union Data d;
d.i = 10;        // 现在这块内存按 int 解释是 10
d.f = 1.23;      // 覆盖！现在按 float 解释是 1.23，原来的 10 没了
strcpy(d.s, "hi"); // 又覆盖
```

**用途**：同一份数据在不同场景下想用不同「看法」（比如网络包里的同一个字段，有时当整数有时当字节数组），或省内存。**坑**：改了一个成员，其他成员的值就废了，别同时读多个成员。

## 7. 一张图看懂「类型决定一切」

```
内存地址   内容        变量
0x1000  |  0001 0010 |  char c = 18;     ← 1 字节，按 char 解释
0x1004  |  0000 0000 |  int  n = 300;    ← 4 字节，按 int 解释
0x1008  |  (8字节)   |  double x = 1.5;  ← 8 字节，按 IEEE754 解释
0x1010  |  0x1000    |  int *p = &c;     ← 指针柜子里放的是 c 的地址
```

同样是 0/1，是「18」「300」还是「1.5」，全看你用的**类型**——这就是 C 把类型看这么重的原因。

## 自测
- `sizeof(char*)` 在 64 位机是多少？→ **8**
- `-1` 的补码怎么来？→ `+1` 取反加 1
- 为什么 `0.1+0.2 != 0.3`？→ 浮点二进制存不下，用「差值 < 精度」比较
- `union` 和 `struct` 最本质区别？→ union 成员**共用内存**、同时只有一个有效；struct 成员**各自占内存**
