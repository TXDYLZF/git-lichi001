# 11 预处理与头文件（大白话版）

> 来源：QQ `08.md`（宏定义 / #include / 防护宏 / extern）
> 函数/头文件基础见 [05-函数](05-函数.md) 第 7 节

预处理指令在**编译之前**由预处理器处理（`#` 开头）。`#include` 把文件内容搬进来，`#define` 做文本替换，`#ifndef` 防重复包含。

---

## 1. #include：搬文件

```c
#include <stdio.h>     // <> 找系统标准库头文件
#include "globals.h"  // "" 先找当前目录，再找系统（自定义头文件用这个）
```

- 作用：搬来函数原型、宏定义、类型定义、外部变量声明。
- 头文件只放「声明」，不放「定义」（避免多重定义）。
- 包含顺序：标准库优先，再自己的，避免循环依赖。

---

## 2. 防护宏：防止头文件被重复包含

同一个头文件被多个 `.c` 间接包含时，声明会重复 → 编译报错。用「守卫」包住：

```c
#ifndef GLOBALS_H
#define GLOBALS_H
// ... 所有声明 ...
#endif
```

现代写法更省事：

```c
#pragma once     // 主流编译器支持：本文件只处理一次
```

---

## 3. 宏定义 #define

不带参（常量替换）：

```c
#define PI 3.1415926
#define MAX_SIZE 100
```

**带参宏**（像函数，但只是文本替换，**不做类型检查**）：

```c
#define SQUARE(x) ((x) * (x))     // ✅ 每个 x 都加括号，防优先级坑
#define MAX(a, b) ((a) > (b) ? (a) : (b))
```

**两个必踩坑**：
1. **参数要加括号**：`#define SQUARE(x) (x * x)` 遇到 `SQUARE(2+3)` 会变成 `(2+3 * 2+3)` = 11（错！）。正确写 `((x)*(x))`。
2. **别带副作用参数**：`SQUARE(i++)` 展开成 `((i++)*(i++))`，`i` 被加两次，结果不可预期。这种场景用 `inline` 函数更安全。

```c
// 多行宏：每行末尾加反斜线 \
#define MULTI_LINE(x) \
  int i = (x);        \
  do { printf("%d\n", i); i--; } while (i > 0);
```

## 4. 字符串化 `#` 与 粘贴 `##`

```c
#define TO_STRING(s) #s
TO_STRING(HELLO)     // 展开成 "HELLO"（加引号）

#define PASTE(a, b) a##b
int value1 = 10, value2 = 20;
PASTE(value, 1)      // 展开成 value1 → 10
```

- `#`：把参数变成字符串字面量。
- `##`：把两段**拼成同一个标识符**（如生成 `value1`）。

---

## 5. #undef：取消宏

```c
#define DEBUG_MODE
#ifdef DEBUG_MODE
  printf("debug on\n");
#endif
#undef DEBUG_MODE          // 取消后，下面的 #ifdef 不成立
#ifdef DEBUG_MODE
  printf("debug on\n");    // 不打印
#endif
```

---

## 6. extern：跨文件共享

`extern` 告诉编译器「这个变量/函数的定义在**别的文件**」，当前只是声明、链接时再找。

```c
// globals.c 里定义
int counter = 10;
// other.c 里用 extern 声明
extern int counter;        // 不分配内存，只声明
```

配合防护宏放头文件里：`extern int counter;`，谁 `#include` 谁就能用。

> 宏 vs inline 完整对比（类型检查 / 调试 / 副作用）见 [05-函数](05-函数.md) 第 5 节 / `07.md`。

## 自测
- `#include <>` 和 `""` 区别？→ <> 系统库；"" 先找当前目录再找系统
- 为什么头文件要防护宏？→ 防止被多次包含导致重复定义报错
- `SQUARE(x)` 为什么每个 x 都要加括号？→ 防运算符优先级踩坑（如 2+3 被拆错）
- `SQUARE(i++)` 为什么危险？→ i 被加两次，行为未定义；改用 inline 函数
